# レンダー「カット一覧」設計

日付: 2026-10-20
状態: 承認済み(設計)

## 目的

レンダーページを、チームがExcelで運用している「レンダリング状況(カット一覧)」と同じ形で
管理できるようにする。カットごとのレンダリング可否・理由・優先度・担当・期限・進行状況を
一目で把握でき、可否・優先度・進行状況はその場で選び直せること。

## 決定事項(ユーザー回答)

- 既存の「共有PCの使用状況」(renderJobs)はカット一覧に**置き換える**(PC使用状況は削除)
- Excel右側の技術的な列(使用コンフィグ・開始/終了フレーム・カメラ名・シーンパス)も**すべて管理する**
- 進行状況は **未着手 / レンダリング中 / やり直し / 完了** の4段階
- 権限は **全員が追加・編集、削除はPMのみ**(「素材」タブと同じ)
- 操作方式は **案A**: 選択式の3項目は表内プルダウンで即保存、その他は「編集」ボタンのモーダル
- Excelからの **一括取り込み機能を付ける**(PMのみ)

## データモデル

新コレクション `renderCuts`(1ドキュメント = 1カット)

| フィールド | 型 | 内容 |
|---|---|---|
| cutNumber | string(必須) | カット番号(例: C001, C023_plus1) |
| renderable | string | `可能` / `不可能` / `''`(未設定) |
| reason | string | 不可/確認中の理由 |
| priority | string | `高` / `中` / `低` / `''`(未設定) |
| assignee | string | 担当(自由入力。「学校(坂井)」のようなメンバー以外の値もあるため) |
| dueDate | string | 期限(`YYYY-MM-DD`、未設定は `''`) |
| status | string | `未着手` / `レンダリング中` / `やり直し` / `完了`(既定 `未着手`) |
| config | string | 使用コンフィグ |
| startFrame | number \| null | 開始フレーム |
| endFrame | number \| null | 終了フレーム |
| cameraName | string | カメラ名 |
| scenePath | string | シーンパス |

`utils.js` に `RENDER_CUT_STATUS_LIST`、`RENDERABLE_LIST` を追加し、優先度は既存の `PRIORITY_LIST` を流用する。
不正な選択値は保存時に既定値(可否・優先度は `''`、進行状況は `未着手`)へ丸める。

## 画面(`docs/js/renderCuts.js`、タブ名は「レンダー」のまま)

1. **集計行**: 「全N カット / 完了 / レンダリング中 / やり直し / 不可能」の件数
2. **ツールバー**: 進行状況の絞り込み(すべて/各状態)、「+ カット追加」ボタン(全員)
3. **一括取り込み**(PMのみ、折りたたみパネル): 後述
4. **表**: 列順はExcelと同じ
   カット番号 / レンダリング可否 / 不可・確認中の理由 / 優先度 / 担当 / 期限 / 進行状況 ‖ 使用コンフィグ / 開始フレーム / 終了フレーム / カメラ名 / シーンパス / 操作
   - 進行状況と使用コンフィグの間に区切り線(左右の境目)
   - `.table-scroll` で横スクロール
   - 可否・優先度・進行状況は `<select>`。`change` で即 `updateRenderCut` → `ctx.refresh()`
   - 色分け: 可能=緑 / 不可能=赤、優先度 高=赤 / 中=黄 / 低=灰、完了=緑 / やり直し=赤 / レンダリング中=青 / 未着手=灰。既存のテーマ変数(`--done` / `--danger` / `--doing` など)を使い、ダークモードでも読めるようにする
   - 長いシーンパスは省略表示し、ホバーで全文(title属性)
   - 「編集」ボタンで全項目を編集できるモーダル。PMにはモーダル内に「削除」ボタン
5. **並び順**: カット番号の自然順(`localeCompare(…, 'ja', { numeric: true })`)。C001 → C023 → C023_plus1

## 一括取り込み(PMのみ)

- テキストエリアにExcelからコピーした範囲を貼り付ける(タブ区切り・改行区切り)
- 列はExcelのA〜L列の順: カット番号, 可否, 理由, 優先度, 担当, 期限, 進行状況, コンフィグ, 開始, 終了, カメラ名, シーンパス
- 1列目が空の行、および1列目が「カット番号」やタイトル行(「レンダリング状況」を含む)の行は読み飛ばす
- 期限は `2026/7/7` 形式を `2026-07-07` に変換。数値でないフレームは `null`
- シーンパスの前後の `"` は除去
- 可否・優先度・進行状況は選択肢と完全一致した場合のみ採用し、それ以外は既定値に丸める
- 「プレビュー」で **新規○件・更新○件** を表示し、「取り込む」で確定
- 同じカット番号が既にあれば上書き(更新)、無ければ新規作成。`writeBatch` で400件ずつ書き込む

## 権限(`firestore.rules`)

```
match /renderCuts/{id} {
  allow read: if signedIn();
  allow create, update: if signedIn() && hasClaim();
  allow delete: if isAdmin();
}
```

既存の `renderJobs` ブロックは削除する。**ルールの再公開が必要**。

## 削除・置き換え

- 削除: `docs/js/renderQueue.js`、`api.js` の renderJobs 系4関数、`utils.js` の `RENDER_STATUS_LIST` / `renderStatusColor`、`app.js` の renderJobs 読み込み、`firestore.rules` の renderJobs ブロック、関連CSS(使われなくなるもののみ)
- 既存の `renderJobs` データはFirestoreに残る(使われないだけ)
- ダッシュボードの「レンダー中」タイル →「レンダー完了 X/Y」タイル(クリックでレンダータブへ)
- `BACKUP_COLLECTIONS` に `renderCuts` を追加。注意: これ以前に作ったバックアップを復元すると、カット一覧は空になる(他コレクションと同じ「置き換え」動作)
- README のレンダー説明・データ保存先一覧を更新

## テスト・確認

自動テストの仕組みが無いため、実装後に以下をブラウザで確認する:
- 追加・編集・各プルダウンの即時保存・絞り込み・集計・並び順
- 一括取り込み(見出し行混在、日付・フレーム変換、上書き/新規の件数表示)
- PM以外で削除・一括取り込みが表示されないこと
- ダークモードでの色の見え方、ダッシュボードのタイル

## 対象外

- 同じ行を2人が同時に編集した場合の競合検知(後から保存した側が勝つ。他タブと同じ)
- カットとタスク・メンバーの紐付け
- Excelへの書き出し
